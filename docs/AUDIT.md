# GrantScope engineering audit

Scope: application transport, ABI/read engines, chain selection, query ownership, BigInt calculations, revocation claims, local state, browser behavior and production output. This is a development audit with regression tests, not an independent security review or proof of complete coverage.

## Follow-up review, 6 November 2026

The master specification and current official EF requirements were checked again. Reproduced defects were fixed with regression tests; this review does not establish that every possible defect has been found.

| Finding                                                                                   | Fix and regression evidence                                                                                                                                                                                                                                  |
| ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Cancelled or unserializable requests named a worker route before dispatch                 | Set actual route only immediately before fetch. Pre-dispatch failures/cancellations retain `none`; in-flight cancellations retain the worker actually called. Header accounting now uses measured counters instead of obsolete “Not measured” copy.          |
| Revocation preparation and post-state were not both anchored                              | Recheck the preparation snapshot and the zero-state block hash as well as the receipt inclusion block. A surviving receipt does not validate a reorganized later state read. Security tests reproduce both cases.                                            |
| Generic ABI decoding accepted trailing words in allowance responses                       | Require exactly one ERC-20 word and three canonical Permit2 words. Shared Permit2 decoding rejects out-of-width uint160/uint48 values and is used in inspection and revocation verification. Malformed zero responses cannot establish revocation.           |
| Leaving the permission screen could leave final preflight running toward a wallet request | Abort preflight on unmount/permission change and check its signal before handoff. A UI regression confirms no send after navigation during preflight. An already handed-off wallet request cannot be cancelled by the app; receipt tracking still continues. |
| Removed queries left assessment summaries visible                                         | Subscribe to removal events as well as data updates. A cache-removal regression checks immediate removal without initiating reads.                                                                                                                           |
| An older higher-block snapshot could override a newer checked snapshot after a reorg      | Reconcile by captured read time, using height only as a tie-breaker. A lower-head regression preserves the later checked result.                                                                                                                             |
| Historical zero activity could hide a later positive read at the same height              | Timestamp successful zero verification and supersede only earlier snapshots. Later positive reads remain actionable. This is historical evidence, not permanent revocation.                                                                                  |
| A cleared ERC-20 dependency left an old Permit2 bound in active counts                    | Withhold the older dependent bound and explain that the stored Permit2 grant was not cleared. Preserve original amounts and require refreshing both layers.                                                                                                  |
| Parallel transforms made lazy-route tests unreliable under host load                      | Bound Vitest to four workers. Keep assertions and timeouts intact; the complete 95-test suite passed with this setting.                                                                                                                                      |

The blocked-bootstrap browser regression intercepts both configured RPC endpoints, permits only fixed specifier selectors, and confirms no inspected address is sent directly. It passed on desktop/mobile in both development and production. Real Nox block/balance reads and the local positive allowance scan also passed; Nym initialization timed out. See [fresh results and reproduction](TESTING.md#follow-up-review-6-november-2026).

## Module 11 findings

| Finding                                                                                          | Fix and evidence                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| SDK cancellation alone could leave a never-resolving fetch pending                               | An outer abort/deadline race bounds the complete fetch/body decode. Already-cancelled operations do not dispatch. Cross-realm AbortError names are recognized. Regression uses a deliberately nonresponsive SDK mock.                                                                                                                      |
| JSON-RPC parser accepted ambiguous envelopes and fractional error codes; body size was unbounded | Reject result/error ambiguity, require integer error codes, bound streamed JSON to 8 MiB and cancel its reader. Raw parser data is never echoed in errors.                                                                                                                                                                                 |
| Wallet listeners attached after authorization, risking a stale initial account/chain pair        | Attach first, take a stable wallet-local snapshot with bounded retry, reject continued changes, and clean up partially registered listeners. Generations prevent stale attempts mutating a newer connection.                                                                                                                               |
| Clearing inspection only cancelled native-account reads                                          | Clear all account, allowance, discovery, Permit2 and local-demo caches, cancel their signals, remove manual pairs and close the worker. Payload-free metrics and transaction activity deliberately remain for the page session.                                                                                                            |
| Static token data was repeatedly fetched for every spender                                       | Reuse metadata and balance only within the same scan/owner/block. Individual allowances remain independent real calls; no cross-session persistent cache is introduced.                                                                                                                                                                    |
| A reorg could mix current state at the same block number                                         | Account, ERC-20 and Permit2 snapshots now recheck canonical block hashes. Changed anchors discard the result. Historical discovery already checked event and range anchors.                                                                                                                                                                |
| A full viem public-action bundle carried unnecessary offchain lookup capability                  | Use a minimal viem client and dedicated receipt action, explicitly disable CCIP reads, and keep all receipt actions on the anonymous transport. The main bundle decreased, although a chunk-size warning remains.                                                                                                                          |
| Old scan assessments could remain after a verified zero read                                     | Mark older records superseded and exclude them from active summary counts. A failed refresh explicitly retains an earlier snapshot rather than presenting a fresh result.                                                                                                                                                                  |
| Settings/methodology still described earlier modules                                             | Replace obsolete unavailable claims with actual selected network/worker state and current limitations. Busy confirmations expose disabled dismissal and restore focus to an available control.                                                                                                                                             |
| Local demonstration data could accidentally enter a public build                                 | Public addresses exist only in ignored `.env.local`. A development-only lazy loader reads them. Production guard rejects the loader and any locally configured address in emitted JavaScript. Tests use environment configuration, not committed target fixtures; configured-address browser tests disable screenshots, video and tracing. |

ABI review checked ERC-20 uint256 amounts and canonical numeric returns, Permit2 uint160 amounts/uint48 expiry and nonce, indexed event layouts, exact expiry boundary, and canonical lockdown tuples. Token metadata excludes control/bidirectional formatting characters and is rendered as text. Registry membership never establishes safety. Unsupported metadata/false-return approval remains unreadable or non-executable rather than guessed.

Revocation review checked connected-owner and network authorization before signing, code-present account refusal, latest positive allowance, simulation, gas/native-balance/nonce constraints, context guards, matching mined calldata/value/nonce, receipt block identity, two confirmations, a fresh zero allowance, and a final canonical anchor. Rejection, revert, replacement with a different intent, timeout, provider failure and nonzero post-state do not establish revocation. Nonce tracking deliberately rejects values beyond safe numeric precision. Two confirmations are not finality. Permit2 lockdown does not invalidate all unused signatures.

Remaining limits: bootstrap/provider and worker trust, anonymous-network connectivity, provider omissions/truncation, bounded historical ranges, unknown/nonstandard token behavior, proxy implementations, unsupported smart-account execution, unseen signatures, wallet-internal traffic, and absent owner-signed live revocation/deployed-site evidence. See [PRIVACY](PRIVACY.md), [REVOCATION](REVOCATION.md), [TESTING](TESTING.md), and [LIMITATIONS](LIMITATIONS.md). No arbitrary-address input is replaced by demo-only behavior.
